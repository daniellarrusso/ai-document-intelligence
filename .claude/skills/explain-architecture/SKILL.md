# Explain Architecture

Inspect the relevant solution/project structure, entry points, dependencies, interfaces, API boundaries and tests.

Explain:
- components and responsibilities
- request/data flow
- persistence/integration boundaries
- authentication/authorisation where relevant
- testing strategy
- important trade-offs
- obvious architectural risks/technical debt

Distinguish between what the code currently does, what it appears intended to do, and recommendations. Do not guess; cite file/symbol locations.
